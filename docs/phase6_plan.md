# 阶段 6 计划：Python数据库访问与核心业务事务

## 1. 选择本阶段的原因

老师要求使用高级语言连接数据库并实现较完整业务。Python连接、事务、日志和安全配置也是后续10万级批量生成及高并发实验的共同基础，因此先完成这一层比直接生成大数据更合理。

本阶段只实现和测试Python业务功能，不执行10万级数据、索引性能、并发压力、在线变更、备份恢复或三项算法实验。

## 2. 业务范围

计划实现一个简单CLI和可复用服务层：

1. 注册网络用户；
2. 创建机主和手机号码；
3. 创建购卡订单，一次购买多个面额的充值卡；
4. 使用卡号和测试密码为指定手机号充值；
5. 查询用户购卡明细；
6. 查询手机号充值历史。

不开发前端、支付接口、短信、微服务或复杂权限。

## 3. Python模块设计

计划文件：

- `src/db_config.py`：从环境变量或隐藏输入读取连接配置；
- `src/db.py`：连接、事务上下文和统一关闭；
- `src/security.py`：测试密码摘要和校验，禁止保存明文；
- `src/services/user_service.py`：注册用户；
- `src/services/mobile_service.py`：机主和号码管理；
- `src/services/purchase_service.py`：订单、明细和充值卡创建；
- `src/services/recharge_service.py`：充值事务；
- `src/cli.py`：本科/研究生课程作业可理解的命令行入口；
- `scripts/run_phase6_python_business.sh`：自动实验唯一入口；
- `requirements.txt`：固定数据库驱动版本。

实现时保持代码规模适中并添加中文注释。

## 4. 事务边界

注册、创建号码、购买和充值分别使用明确事务。购卡事务必须原子写入订单、订单明细和多张卡；任一步失败则全部回滚。充值事务验证卡号和测试密码、手机号存在后插入 `recharge_record`，由阶段5触发器校验面额并更新卡状态；程序捕获业务错误并回滚。

数据库UNIQUE、FK、CHECK和触发器仍是最终完整性防线，Python不绕过这些约束。

## 5. 自动化测试数据与安全

- 所有数据使用 `P6` 专用标记；
- 测试前拒绝已有P6数据，避免盲目重复；
- 自动测试在受控事务或明确清理边界内运行，不修改P4数据；
- 运行前后核对P4基准以及P5视图/触发器仍存在；
- 密码通过隐藏输入或权限600的临时配置传递，不进入命令行、Git或日志；
- 日志写入 `results/phase6/`，原始日志默认不提交。

## 6. 自动验证场景

单一入口计划自动验证：

1. Python驱动连接OceanBase CE 5.0.1.0 MySQL租户；
2. 用户注册成功，重复登录名被拒绝；
3. 一个机主创建两个手机号；
4. 一个订单购买多张不同面额卡；
5. 正确卡号、密码和金额充值成功；
6. 密码错误、手机号不存在、卡已使用和重复充值失败；
7. 购卡视图和充值历史视图返回正确结果；
8. 失败事务没有半成品数据；
9. P4基准未改变，P5对象仍完整；
10. 最终输出PASS/FAIL并保存无密码日志。

## 7. 单一入口

计划入口：

```bash
bash scripts/run_phase6_python_business.sh
```

入口脚本将检查Python版本和依赖、隐藏读取一次数据库密码并执行自动测试。依赖安装方式和是否创建项目虚拟环境需在实现阶段经ChatGPT审核后确定。
